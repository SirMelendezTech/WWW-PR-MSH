# AGENTS.md

PRMSH community site for the Puerto Rico Meshtastic mesh: static Astro build, bilingual, deployed to GitHub Pages at `https://meshtastic.prmsh.com`. Layout and commands: `README.md`. Human contribution flow and frontmatter shapes: `CONTRIBUTING.md`.

## Workflow

- Start the dev server in background mode: `astro dev --background`. Manage it with `astro dev stop`, `astro dev status`, `astro dev logs`.
- Verify with `npm run build`. There are no tests or linter; a clean build is the gate.
- Work on a branch and open a PR. Every push to `main` deploys production.
- Commits follow Conventional Commits with a scope: `feat(how-it-works): …`, `docs(hardware): …`, `chore(gitignore): …`.

## Bilingual by default

Spanish is the default locale at `/`; English lives under `/en/`. Every user-facing change ships in both languages.

- Build every internal href with `localizePath(path, lang)` (`src/lib/i18n.ts`) or `blogPostHref(lang, id)` (`src/lib/blog.ts`). A hardcoded `/en/` or `/es/` prefix breaks the language switch.
- UI copy lives in `src/lib/ui-strings.ts`. The `en` object is the source of truth; `es` must match its shape. Client `<script>` blocks cannot import the dictionary, so pass their strings through `data-i18n-*` attributes.
- Page bodies are `src/components/pages/*Content.astro` taking a `lang` prop. `src/pages/x.astro` (ES) and `src/pages/en/x.astro` (EN) stay thin wrappers.
- Docs: English at `src/content/docs/<slug>.md`, Spanish at `src/content/docs/es/<slug>.md` with `lang: es`.
- Spanish cross-doc anchors use the accented Spanish heading slug (`#región-y-frecuencia`). This config ignores `{#custom-id}`.
- Blog: new posts use `-en` / `-es` filename suffixes and share a `translationKey`. Leave older unsuffixed filenames as they are: renaming changes the URL.

## Brand and domain

- The brand is **PRMSH**. "Meshtastic" only describes the technology ("PRMSH — Comunidad Meshtastic de Puerto Rico"). Meshtastic trademark rules forbid "Meshtastic PR" or "Meshtastic Puerto Rico" as a name.
- Absolute URLs for this site use `https://meshtastic.prmsh.com`. Bare `prmsh.com` is a separate landing page.

## Content rules

- `<details>` holds secondary material only: long reference tables, optional checklists, edge-case config. Core explanations, required steps, and safety warnings stay visible.
- Recommended Settings (`settings.md`, both languages) is for app users: Android and iPhone menu paths with platform icons, never `meshtastic --set` commands.

## Gotchas

- Astro caches rendered Markdown. After editing a rehype plugin in `plugins/`, delete `.astro/data-store.json` before building, or the old output persists.
- The node map reads `https://malla.prmsh.com/api/locations` at build time in `src/lib/nodes.ts`. That API sends no CORS headers, so the map refreshes only on rebuild (scheduled on the 1st and 15th in `.github/workflows/astro.yml`). Leave the optional `MALLA_API_TOKEN` path in place.
- GitHub Pages serves the root Spanish `404.html` for every miss, `/en/*` included. `public/_redirects` only works on Netlify or Cloudflare Pages.
- Old URLs (`/es/*`, old English blog posts) resolve through static redirect stubs generated by `redirects` in `astro.config.mjs`. Keep that block in sync when moving a page.
